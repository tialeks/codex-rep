# Анкета и получение ответа

В ChatGPT Work, где доступна inline-визуализация, **всегда** показывать готовую интерактивную анкету до генерации. Это обязательный первый результат вызова скилла, включая короткие запросы «сгенерируй шайбу», «используй скилл» и обращения с уже приложенным логотипом. Не выдавать вместо неё список вопросов, JSON, ссылку для скачивания HTML или обещание открыть анкету позднее.

Порядок вывода в ChatGPT Work:
1. Прочитать полные актуальные инструкции скилла `visualize`.
2. Скопировать **без переработки** готовый HTML-фрагмент `assets/questionnaire.html` в новый файл `/workspace/service-shaiba-form.html` (или уникальное имя в `/workspace`, если файл уже занят). Это именно HTML-фрагмент без `<html>` и `<body>`.
3. Проверить существование созданного файла и что в нём есть кнопка `Подтвердить и создать шайбу`.
4. В **финальном** ответе этой же очереди вывести отдельной строкой нативную ссылку `visualize{"path":"/workspace/service-shaiba-form.html"}` (подставить фактический абсолютный путь). Не использовать `sandbox:` или обычную Markdown-ссылку: они не откроют форму внутри чата. После этого ждать нажатия кнопки, которая отправит параметры в чат.

Если попытка вывода не удалась или пользователь указывает, что анкета не появилась, повторить шаги 1–4 с новым файлом и показать форму; не заменять её текстовыми вопросами при доступной inline-визуализации. Уже подтверждённые параметры и правки текущей шайбы не требуют повторной анкеты. Не ссылаться на HTML как на уже подключённую генерацию.

В клиенте без inline-визуализации предоставить `assets/questionnaire-standalone.html`. Только если ни inline-форма, ни HTML-файл не могут быть показаны, использовать один полный текстовый опрос:
1. General color: Solid + HEX или Gradient + 2–6 HEX по порядку и направление.
2. Логотип: приложить новый для этой шайбы (если не приложен вместе с её запросом).
3. Удалить фон: да / нет.
4. Размещение: S / M / L / full surface / На грани.
Геометрия и свет закреплены. Попросить подтвердить полный набор ответов.

Кнопка HTML отправляет подтверждённые параметры как следующее сообщение в чат через поддерживаемый интерфейс `window.openai.sendFollowUpMessage`. Если **новый** логотип для данной задачи уже приложен вместе с новым запросом или после него, сразу начать генерацию. Иначе после подтверждения попросить новый файл обычным сообщением, сохранив параметры анкеты, и начать генерацию сразу после получения. Вложение нельзя передать из inline-формы. Не требовать JSON или повторной анкеты. В клиенте без этого интерфейса форма показывает готовый текст запроса для ручной отправки; не обещать автоматическую генерацию в таком клиенте.

Не брать логотип из предыдущей завершённой шайбы. Поле загрузки из формы убрано, так как оно не передавало файл ассистенту. При новой задаче всё равно сначала показать анкету; после ответа получить новый исходник до генерации, если он ещё не приложен в рамках этой задачи. При коррекции текущей шайбы продолжать с её исходником без повторного запроса. Не пропускать анкету из-за наличия файла или полностью описанных параметров новой задачи.
