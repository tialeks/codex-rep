# Service shaiba

## Начинать с анкеты

1. Для каждой новой задачи на лого-шайбу показать `assets/questionnaire.html` ДО генерации, даже если исходный запрос содержит логотип, цвет и размер. Прочитать `references/form-flow.md` для вывода и получения результата. Не переписывать форму заново.
2. Считать параметры из исходного запроса только предложениями для заполнения, а не подтверждением анкеты. Ранее приложенный логотип сохранить как доступный исходник; повторная загрузка не обязательна. Не начинать генерацию по заполненным значениям без отправки/подтверждения анкеты.
3. Использовать подтверждённые ответы анкеты вместо противоречащих им более ранних пожеланий. Не выдавать значения по умолчанию за выбор пользователя. Не запускать опрос заново при ответе на него или коррекции текущей задачи.
4. Если дизайнер ЯВНО просит нарушить правила, обойти анкету, изменить фиксированную геометрию/свет или использовать собственные правила вместо скилла, спросить: **«Игнорируем правила скилла и используем ваши параметры?»** Перед вопросом кратко назвать конкретные отступления. Только после явного «да» применить эти отступления и генерировать по параметрам дизайнера, если исходник и необходимые параметры доступны. При «нет» вернуться к анкете; молчание не считать согласием. Сохранить все не затронутые исключением правила. Не спрашивать повторно о том же уже подтверждённом исключении.
5. Не трактовать обычное «сделай красную M» как просьбу обойти правила. Не применять исключение к требованиям платформы и безопасности: скилл регулирует только дизайн-процесс. Прямые инструкции пользователя имеют приоритет в рамках системных правил.

## Параметры

- `general_color`: `solid` (один HEX) или `gradient` (2–6 HEX-точек, порядок и направление). Заливка покрывает лицевую поверхность И боковину. Свет добавляет оттенки, но не заменяет цвет. При прозрачном исходнике заливка видна под ним; при сохранённом непрозрачном фоне исходника тот перекрывает соответствующую область лица.
- `logo`: приложенный/выбранный файл логотипа или иллюстрации. Поддерживать монохромные, цветные, градиентные знаки и outline. Не перерисовывать и не менять фирменные цвета произвольно.
- `remove_background`: да/нет. Удалять только фон исходника, не белые детали внутри знака. Прозрачный исходник не требует повторного удаления. Для неоднозначного удаления показать результат до генерации.
- `placement`: ровно одно из `S`, `M`, `L`, `full surface`, `На грани`.
  - S: большое поле; знак «Я» вместе с красной подложкой.
  - M: среднее поле; Burger King.
  - L: малое поле; округлый градиентный знак.
  - full surface: без поля, обрезать изображение по контуру лицевой поверхности, НЕ переносить рисунок на боковину; Билайн.
  - На грани: крупный рисунок непрерывно переходит на боковые поверхности с учётом геометрии; Афиша, графический знак и outline-иконка.
- Центрировать S/M/L относительно лица, не общего силуэта с боковиной. Сохранять завершённый контур цветного логотипа целиком. Масштабировать весь знак/подложку. Перспектива может сделать видимые поля неравными. Не придумывать точные проценты S/M/L: эталоны визуальные.

## Постоянные

Открыть `assets/geometry.png` и `assets/lighting.png`, затем только референс выбранного размещения из `references/references.md`. Сохранять силуэт, разворот, перспективу, толщину, положение и относительный размер шайбы по geometry. Использовать мягкий верхний блик и лёгкую нижнюю подсветку по lighting, без лишних засветов. Форма/свет не являются полями анкеты.

## Генерация и проверка

- После подтверждения проверить наличие доступного исходника и корректных цветов. Inline-форма отправляет параметры сообщением в чат, но не загружает файл: если логотип отсутствует в разговоре, попросить приложить его и затем сразу генерировать без новой анкеты. Не придумывать логотип.
- Использовать доступный инструмент генерации/редактирования изображений, соблюдая его актуальные инструкции; передать реальные локальные файлы geometry, lighting, выбранного размещения и исходник. Не подставлять Figma URL вместо изображения. Для серии использовать тот же геометрический эталон при каждой генерации.
- Сформировать задание из подтверждённых параметров: точный исходник, general color, размещение, фон, фиксированные геометрия и свет. Отделить фон логотипа от фона итогового изображения; сохранять прозрачность внешнего фона, если не указано иное.
- Проверить силуэт, разворот, толщину, поля, цвета, сохранность знака, обрезку/переход, свет. Исправить заметные отклонения. Не обещать пиксельно одинаковую геометрию от вероятностной генерации; для строгой идентичности требуется общий 3D/композитный шаблон, которого в пакете нет.
- Не обращаться в Figma при обычной генерации: локальные эталоны уже включены. Эталон geometry.png — 950×950 и имеет приоритет для разворота и толщины боковины; остальные локальные эталоны 40×40 и задают лишь визуальное направление. Не увеличивать наклон и толщину относительно geometry.png. При необходимости точного большого результата запросить высококачественный исходник вместо выдумывания деталей.

## Переносимость

Установить всю папку как скилл, сохранив assets и references. Открытие ZIP само по себе не устанавливает скилл. В среде с inline HTML показывать анкету в разговоре; иначе предоставить приложенный standalone HTML и ту же текстовую анкету. Не обещать одинаковый интерфейс в клиентах без поддержки HTML или генерации. Явный вызов: `$service-shaiba`. Автоматический выбор зависит от обнаружения установленного скилла средой.
