# Проверка PNG и приёмки

Команда проверяет целостность доказательств, а не художественное качество. Нужны pin из prepare, receipt с `record-submission --generated-file` и ручной review фактического PNG.

Review — JSON с абсолютным `file`, фактическим `sha256`, общим `status` и объектом `checks`. Обязательные проверки: `form`, `materials`, `light`, `composition`, `colors`, `style_fidelity`; для каждого выбранного свойства референса — `reference_<facet>`. Каждая содержит `status` (`pass`, `limited`, `fail`) и `observation`: конкретное наблюдение не короче 20 символов. Для референса нужно сравнение с привязанной картинкой.

Любой fail требует общего fail. Общий pass допустим только при всех pass; оставшееся ограничение сохраняет limited. Текст наблюдения заполняется после просмотра: скрипт не определяет его правдивость.

```sh
python3 scripts/review_result.py --execution /absolute/execution --file /absolute/result.png --review /absolute/review.json --expected-manifest-sha256 <PIN_FROM_PREPARE>
```

Проверяются аргументы, связь receipt с manifest и SHA результата, структура review, декодируемые пиксели PNG и наличие неполностью непрозрачных пикселей при запросе прозрачности. `evidenceValid: true` не меняет художественный статус. Файлы не изменяются.

Архивирование через `history.py --import-attempt` также проверяет доказательства, но допускает непрозрачный PNG при запросе прозрачности только с общим `fail`. Такой результат должен оставаться видимым в истории. Ошибка строгой проверки прозрачности не разрешает потерять попытку или выдать её за принятую; `complete` её отклоняет.

Проверка использует Pillow для обычных PNG и отдельный декодер для точной прозрачности 16-битных PNG. Неподдерживаемый вариант — 16-битный Adam7; предел — 64 млн пикселей и 512 МБ распакованного потока. При таком ограничении не заявляй успешную проверку. Manifest без pin или receipt только с ID вызова не подтверждает происхождение PNG.
