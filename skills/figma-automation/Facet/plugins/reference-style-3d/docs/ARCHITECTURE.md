# Устройство проекта

## Рабочий путь

1. `build_browser.py` создаёт боковую студию, `serve_presets.py` обслуживает её только на localhost. `render_controls.py` читает палитры, визуальные пресеты и карты материалов, создаёт форму из `ui/controls.html` без записи в личную библиотеку.
2. Форма через локальную очередь отправляет `schemaVersion: 1` со `settingsVersion: 3`. Отправленный снимок определяет параметры отдельного задания.
3. Агент описывает сцены. `compile_settings.py` проверяет параметры; `prepare_generation.py` соединяет их с активным стилем и ролями входов.
4. Prepare сохраняет запрос, промпт, профиль и копии изображений. Verify сверяет их с внешним pin и возвращает точные аргументы встроенного imagegen.
5. `record-submission` связывает фактический PNG с исполнением. `review_result.py` проверяет файлы и ручной review; художественное сравнение выполняет агент по оригиналам.

## Источники истины

| Область | Источник |
|---|---|
| Оси графики | `references/graphics.json` → `graphics.py` и форма |
| Приёмы | `references/effects.json` |
| Свойства пользовательского референса | `references/reference-facets.json` → `reference_guidance.py` и форма |
| Материалы | `assets/materials/catalog.json` → `material_library.py` и форма |
| Оригиналы | `references/sources.json` → `assets/originals` |
| Язык рендера | `references/prompt-profile.json` → `style.txt` |
| Проверка настроек | `compile_settings.py` |

Здесь `references/` обозначает `skills/reference-style-3d/references/`, скрипты находятся в `scripts/`. Промпт содержит содержание сцен, общий стиль, роли реально приложенных изображений и один блок настроек. Документация подготовки не вставляется в него целиком.

## Границы состояния

Форма хранит текущие параметры. Палитры, наборы материалов, визуальные пресеты, превью, история и избранное находятся во внешнем личном каталоге `~/.local/share/reference-style-3d` или `REFERENCE_STYLE_3D_DATA_DIR`, с атомарной записью и проверкой результата. Контракт применения и сохранения — в [presets.md](../skills/reference-style-3d/references/presets.md). Пресет сохраняет текущий сюжет, заменяет параметры оформления и отключает референс. Исполнение хранит неизменяемый отправленный снимок; правки формы не меняют его. История и задания находятся во внешнем личном каталоге; подготовка исполнений и отчёты — в рабочем каталоге задачи. Никакие пользовательские результаты не записываются в пакет. В `assets/` лежат зарегистрированные оригиналы, карты материалов и встроенная коллекция пресетов с превью. Это библиотека оформления; пользовательские исполнения в пакет не попадают.

Выбранные свойства референса замещают только свои ручные настройки в эффективном представлении; исходный снимок сохраняется. Входы STYLE, MATERIAL, CONTENT, COMPOSITION, GUIDANCE и EDIT SOURCE имеют разные роли. Карта поверхности не является источником геометрии или цвета. Правила переноса — в [reference-guidance.md](../skills/reference-style-3d/references/reference-guidance.md).

## Совместимость

Версия снимка настроек, версия manifest и версия профиля — независимые контракты. Настройки исполняются по указанной версии без неявной миграции. Проверка сохранённого исполнения использует его файлы, а не актуальный мастер-промпт.

Команды и границы проверок — в [VALIDATION.md](../VALIDATION.md).

## Локальное выполнение

`listen_requests.py` забирает снимки из очереди и поддерживает ограниченную по времени lease. Отключение останавливает новые захваты; уже отправленные генерации завершаются отдельно. Ожидание работает в активном ходе Codex и не является системным сервисом автозапуска.

Для запуска требуются Python 3.9+ и Pillow; Node.js нужен только для проверок разработчика. Файловые блокировки используют POSIX `fcntl`, поэтому текущая локальная реализация предназначена для macOS/Linux.

## Встроенные пресеты

`assets/presets/` содержит переносимую коллекцию настроек и WEBP-превью. Она доступна после установки без копирования истории автора. Личные пресеты, избранное и генерации хранятся отдельно от пакета.
