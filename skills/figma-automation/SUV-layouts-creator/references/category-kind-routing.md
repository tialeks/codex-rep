# Приоритетный выбор вида категории

Уточнение пользователя 3 ноября 2026: поле называется **«Вид категории»**. Два варианта:
- **Задание с наградой**;
- **Категория кэшбэка**.

Это верхний уровень сценария: сначала определить его, потом тип Internal/External/партнёр, источник выгоды, способ оплаты и оформление. Не переименовывать его в «вид кэшбэка», не добавлять «задание» пятым источником рядом с селектором/крутилкой/уровнем/Балдежом. Ветка обычной категории сохраняет ранее поддержанные скидки и прочие варианты выгоды.

## Форма в чате

Выбор вида размещён выше выбора таблицы/ручного заполнения. Он применяется к текущему набору; внутри отдельной категории и отдельного табличного источника можно выбрать вид независимо, чтобы поддержать смешанные материалы. Новые категории и источники наследуют верхний выбор. Дублирование сохраняет свой вид и собственные поля.

Ручная ветка задания собирает отдельно:
- получаемую категорию (название, Internal/External/партнёр, описание шторки, ставка и условия получаемой выгоды);
- вид задания из трёх [согласованных](task-types-progress.md);
- сервис выполнения задания;
- число транзакций для двух счётных видов;
- минимальную сумму засчитываемой транзакции для вида с определённой суммой либо общую целевую сумму для POS-оборота;
- метод оплаты выполнения задания: карта Пэй / любая карта / любая карта через кнопку Яндекс Пэй;
- ссылку CTA в сервис выполнения, если известна.

Не смешивать сумму активации с порогом уже полученной кешбэк-категории. Аналогично не смешивать метод оплаты задания с методом получаемой выгоды; когда в исходных данных один метод явно относится ко всему сценарию, можно использовать его совместно. Разные методы не подменять друг другом.

Задание всегда передаётся как не начатое, current=0; поле обычного подстрочника ячейки скрыто и очищается в передаваемых данных. Источник выгоды обычной категории не назначается заданию автоматически (не ставить Selected-сердечко по оставшемуся selector). Для «любой суммы» скрытая сумма не передаётся; для POS-оборота скрытое число транзакций не передаётся. При переключении обратно в обычную категорию поля задания не попадают в результат.

## Таблицы, скриншоты и смысловое распознавание

Проверять заголовки, отдельные колонки, пояснения и сами условия. Формулировки «задание», «задание с наградой», «категория с наградой», «выполнить задание, чтобы открыть/активировать категорию» и смысловые производные обозначают эту механику. Искомый смысл — **условие действия, за которое открывается категория**, а не точное совпадение одной строки.

Упоминание награды/вознаграждения само по себе в описании обычного кешбэка не доказывает наличие задания. Не путать обычный порог «кешбэк при покупке от X» с отдельным действием для активации награды. При неоднозначности спросить, а не достраивать механику.

Для каждого задания выделить получаемую категорию, сервис действия, вид задания, цель и метод оплаты. Они могут относиться к разным сервисам. Явный выбранный вид имеет приоритет над общим оформлением обычных категорий; если он противоречит ясным условиям таблицы, уточнить конфликт до сборки. Отсутствие отдельной колонки вида не является основанием игнорировать явно описанное задание.

Источники ссылок и группы нескольких скриншотов остаются независимыми. Внутри одного материала могут быть разные виды категорий: классифицировать строки по смыслу и не размечать весь лист по одному случайному слову.
