# Ячейки категорий в списке СУВ

Правила согласованы пользователем 2 ноября 2026 по присланным скриншотам таблиц и ячеек. Структура External-only «Все покупки» дополнительно проверена в Figma: [2844:106924](https://www.figma.com/design/vdZ2J9y2d01k7UrmIbIfnR/SELECTOR?node-id=2844-106924), вложенный List-item `2844:106935`.

## Роль ячейки

- Ячейка — компактный List-item в списке СУВ. При подготовке категории нужны **и ячейка, и детальная шторка**, чтобы контентщикам хватало фактуры.
- Название в ячейке, описание под заголовком шторки, подстрочник ячейки и подстрочник выгоды внутри шторки — разные текстовые роли. Не подменять одну другой.
- Слева — соответствующая иконка/логотип категории, у двойной категории — два знака. Справа — ставка и знак соответствующего типа выгоды.
- Для кешбэка сохранять процент и символ Плюса; для скидки — числовое значение и иконку Percent вместо Плюса, не дублировать «%» в числовой подписи.
- Не переносить автоматически в ячейку весь набор условий деталки, её описание или строку «Категория месяца» вместо названия категории.

## Когда включать подстрочник

- Общее правило для категорий: подстрочник включать, **если есть уточняющее условие**, которое нужно показать в ячейке. Без уточнения выключать.
- Это касается и External, и Internal, и «Все покупки» только External. Отсутствие подстрочника в отдельном примере не запрещает включить его для нового уточняющего условия.
- **Исключение: у партнёрских категорий обычный текстовый подстрочник с условиями выключен.** При этом бейдж метода оплаты всегда включён: строку 2nd line, содержащую бейдж, не отключать. См. раздел партнёрских бейджей ниже.
- Подстрочник кратко уточняет тип/объект выгоды, период, тарифы или область покупки по соответствующему случаю; не превращать его в полный юридический текст.
- Длинное уточнение переносится на несколько строк без обрезки: текст и контейнеры FILL по ширине/HUG по высоте, truncate выключен, не фиксировать высоту по скриншоту.

| Кешбэк на первый месяц ОСАГО | ОСАГО с Заботой | Кешбэк на первый месяц |
| Такси, выбранные тарифы | Яндекс Такси | Тарифы «Комфорт», «Комфорт+» и «Ultima» |

Формулировки и числа из конкретных примеров не становятся универсальными условиями.

### Еда и Деливери

По таблице: 100% скидка на доставку, минимальная покупка 1000 ₽, карта Пэй.
В ячейке: два знака сервисов, название «Еда и Деливери», подстрочник «Скидка на доставку», справа число 100 и иконка Percent.
Порог 1000 ₽ раскрывается в деталке; не переносить его автоматически в этот подтверждённый подстрочник.

### ОСАГО

По таблице: 100% кешбэк на первый месяц подписки ОСАГО, до 3000 баллов за покупку и до 10 000 баллов за период, любая карта.
Ячейка: «ОСАГО с Заботой», «Кешбэк на первый месяц», справа 100% со знаком Плюса.
Лимиты сохранять в деталке. Не смешивать первый месяц выгоды и срок начисления баллов.

### Такси

В подстрочнике ячейки обязательно показывать тарифный охват по условиям:
- ограниченные тарифы — «Тарифы «Комфорт», «Комфорт+» и «Ultima»»;
- без ограничений — **«Все тарифы»**, а не «На все тарифы» из подстрочника выгоды внутри деталки.

Слева в ячейке логотип Такси, справа ставка со знаком Плюса. Сердечко Selected из строки выгоды деталки не заменяет логотип в компактной ячейке. Параметры ставки и оплаты из примера 5%/карта Пэй не универсальны.

### Кинопоиск и Музыка

Если есть уточняющее условие, показывать его в подстрочнике ячейки. Без уточнения выключать.
Подтверждённая формулировка Кинопоиска: «За покупку билетов». В примере ставка 10%, лимит 2000 баллов, любая карта; в ячейку вынесено только уточнение про билеты, лимит и метод оплаты раскрываются в деталке.
Для Музыки использовать её фактическое условие, не переносить формулировку про билеты.

## «Все покупки»: различать охват

### Комбо External + Internal

- Название всегда **«Все покупки»**.
- Подстрочник всегда **«В сервисах Яндекса и вне»** для такого охвата.
- Визуально в примере общий знак покупок дополнен знаком Яндекса.
- Пример 3%, 300 баллов за транзакцию и 5000 в месяц: ставка в ячейке, лимиты в деталке. Эти числа не являются значениями по умолчанию.

### Только External

Проверено по `2844:106924`:
- `Cell Leading · Master component set / Lock Icon=false` (фактическое имя свойства `Lock Icon#2931:12`).
- `Option=graphics`.
- Название **«Все покупки»**.
- Не писать о сервисах Яндекса в подстрочнике.
- В данном примере `center / 2nd line=false` (фактическое свойство `2nd line#3384:2`).
- По последнему уточнению пользователя **при наличии других уточняющих условий подстрочник можно включать**; отсутствие строки в эталоне не является безусловным запретом.

Не переключать Lock Icon у всех категорий по этому частному примеру: правило задано для «Все покупки» только External.

## Проверка

Проверить ячейку вместе с соответствующей деталкой: название и регистр из условий, иконка/пара знаков, ставка и тип выгоды, нужный подстрочник или его отсутствие, тарифный/временной охват, отсутствие обрезки, отсутствие неуместного текста о Яндексе у External-only. Для партнёров отдельно проверить выключенное текстовое уточнение и включённый бейдж метода оплаты.

## Партнёрские ячейки: обязательные бейджи метода оплаты

Уточнено пользователем и проверено в Figma 2 ноября 2026. **Для партнёров бейдж метода оплаты всегда включён.** В ячейке может быть один или несколько бейджей по её условиям. Это отдельные бейджи оплаты под названием, а не текстовый подстрочник с условиями и не Badge Plus со ставкой справа.

Правило «у партнёров нет подстрочника» означает отсутствие **обычного текстового уточнения выгоды**, а не выключение всей второй строки, если она содержит обязательный бейдж оплаты.

### Подтверждённые формулировки

| Входное условие оплаты | Текст бейджа | Эталон конфигурации |
| --- | --- | --- |
| По карте Пэй | **карта Пэй** | [2549:102352](https://www.figma.com/design/vdZ2J9y2d01k7UrmIbIfnR/SELECTOR?node-id=2549-102352) |
| Через Яндекс Пэй / кнопка Пэй | **через Яндекс Пэй** | [2549:102651](https://www.figma.com/design/vdZ2J9y2d01k7UrmIbIfnR/SELECTOR?node-id=2549-102651) |

Сохранять строчную первую букву в этих текстах. В обоих примерах слева внутри бейджа — **YandexFilled**, не Bank Card / Pay Card. Не смешивать оформление бейджа ячейки с плашкой Accent Bar внутри деталки. Названия партнёров и ставки в примерах не являются частью конфигурации.

### Реальные настройки

- `center / 2nd line=true` (свойство `2nd line#3384:2`) для строки с бейджем; `3d line=false`, `progress=false`, Center content=selector.
- Во второй Line: `Before=false`, `Center=true`, `After=false`, `Trailing=false`, Size=4xs, Style=default.
- Badge помещён в Center Slot этой Line, текстовые text-before/text-after выключены.
- **Badge:** Size=2xs, View=inverted-soft, Type=label, Font weight=Regular, Leading=true, Trailing=false.
- В Leading бейджа: **YandexFilled / Size=12 / Style=Outline** — именно так называется вариант в файле.
- Текст Badge — «карта Пэй» или «через Яндекс Пэй» по входному способу оплаты.
- Ставка и символ Плюса справа сохраняются в отдельном Badge Plus и не считаются бейджем метода оплаты.

Подтверждены примеры с одним бейджем и пример переноса двух бейджей по доступной ширине; см. раздел «Несколько бейджей: перенос по доступной ширине». Универсальный приоритет методов оплаты отдельно не задан.

### Проверка

Для партнёра проверять отсутствие обычного текстового подстрочника с условиями **и наличие хотя бы одного бейджа оплаты**. Не выключать 2nd line механически только из-за партнёрского типа. Не выводить «кнопка Пэй» вместо подтверждённого текста «через Яндекс Пэй».

## Несколько бейджей: перенос по доступной ширине

Правило задано пользователем и проверено по [ADAMAS, 2538:100057](https://www.figma.com/design/vdZ2J9y2d01k7UrmIbIfnR/SELECTOR?node-id=2538-100057) 2 ноября 2026.

- Сначала включить вторую строку center и расположить бейджи оплаты inline в её Line / Center Slot.
- Проверить фактическую доступную ширину Line: бейджи вместе с промежутками должны помещаться целиком. Не ориентироваться только на ширину экрана (360 px в мобильном примере) или только на количество бейджей; учитывать логотип слева, ставку справа, поля и gap.
- Если бейдж не помещается или обрезается, включить третью строку: фактическое свойство **`3d line#3414:0=true`** (пользователь называет third line).
- В третью Line / Center Slot перенести **целый не поместившийся бейдж**. Не обрезать текст, не сжимать бейдж и не уменьшать шрифт ради одной строки.
- Если из трёх бейджей два помещаются в одну Line, оставить эти два inline, третий разместить на следующей строке.
- Если все помещаются во второй Line, не включать третью строку без необходимости.
- Проверять при реальной целевой ширине, включая десктопную; перенос определяется вместимостью конкретной Line.
- Ячейка и center растут по высоте по содержимому. Сохранять оформление бейджей и выключенные текстовые Before/After у строк, содержащих только бейджи.

### Измерения эталона

- List-item: 288 × 56; center: 180 × 56.
- Заголовок: 20 px high; вторая и третья Line: по 16 px; gap между строками 2 px.
- Вторая строка: **«через Яндекс Пэй»**, Badge 115 × 16.
- Третья строка: **«карта Пэй»**, Badge 75 × 16.
- Вместе бейджи занимают минимум 190 px даже без gap, поэтому не помещаются в Line шириной 180 px.
- У center включены и `2nd line#3384:2`, и `3d line#3414:0`.
- Обе строки бейджей: Center=true, Before=false, After=false, Trailing=false, Size=4xs, Style=default.
- Данные размеры и расположение описывают этот пример; не фиксировать по ним ширину/высоту всех ячеек и не выводить из одного примера универсальный приоритет методов оплаты.

## External и Internal: через Яндекс Пэй + уточнения

Принцип задан пользователем и проверен по [2858:107971](https://www.figma.com/design/vdZ2J9y2d01k7UrmIbIfnR/SELECTOR?node-id=2858-107971) 2 ноября 2026. Конкретные название, ставка и уточнение примера не являются обязательными данными этого сценария.

- Если для **External или Internal** задана оплата **через Яндекс Пэй / кнопкой Пэй**, включить **2nd line** и поставить туда бейдж **«через Яндекс Пэй»**.
- Дополнительные уточняющие условия размещать **текстом в Third Line**, включив фактическое свойство `3d line#3414:0=true`.
- Не смешивать дополнительное условие с текстом бейджа и не занимать им вторую строку, отведённую для бейджа.
- Третья строка здесь появляется из-за наличия **дополнительных условий**, а не только при переполнении бейджей, как у партнёров.
- Если дополнительных условий нет, пустую третью строку не добавлять.
- Этот сценарий разрешает бейдж оплаты и текстовое уточнение у External/Internal. Не переносить на него запрет текстовых уточнений партнёров.

### Настройки проверенного примера

- Заголовок: «Яндекс Заправки».
- Вторая строка: бейдж «через Яндекс Пэй».
- Третья строка: текст **«Только на Лукойл»** — только условие данного примера, не универсальный текст.
- center: 2nd line=true, 3d line=true, progress=false, Center content=selector.
- Вторая Line: Center=true, Before=false, After=false, Trailing=false; Size=4xs, Style=default. Badge находится в Center Slot.
- Badge: Size=2xs, View=inverted-soft, Type=label, Font weight=Regular, Leading=true, Trailing=false; YandexFilled / Size=12 / Style=Outline слева.
- Третья Line: **Before=true, Center=false, After=false, Trailing=false**, Size=4xs, Style=default. Уточнение находится в text-before, это текст, не ещё один бейдж.
- Дополнительное условие и ставка берутся из текущих входных данных; воспроизводить принцип распределения по строкам, а не все данные примера.

## Связь бейджей ячейки и нескольких методов в деталке

По уточнению пользователя от 2 ноября 2026:
- **«через Яндекс Пэй» уже подразумевает оплату любой картой**. Для этого же метода не добавлять дублирующий бейдж **«любая карта»**.
- Если у категории действительно два самостоятельных метода оплаты (например, через кнопку Пэй любой картой и картой Пэй), показать соответствующие два бейджа: **«через Яндекс Пэй»** и **«карта Пэй»**.
- Два бейджа отражают два предложения, подробно раскрытых отдельными блоками в шторке. Это не две подписи одного способа оплаты.
- Одинаковая ставка не объединяет методы: могут различаться условия, каналы покупки и ограничения. Сопоставлять бейджи со всеми предложениями деталки.
- Чаще этот случай встречается у партнёров, но число методов определяется условиями конкретной категории.
- Ячейка ADAMAS [2538:100057](https://www.figma.com/design/vdZ2J9y2d01k7UrmIbIfnR/SELECTOR?node-id=2538-100057) и шторка под ней [2549:101786](https://www.figma.com/design/vdZ2J9y2d01k7UrmIbIfnR/SELECTOR?node-id=2549-101786) проверены как связанная пара.
- Бейджи распределять по строкам по уже заданной проверке ширины. Контейнер и отступы двух предложений деталки — в [partner-category-wording.md](partner-category-wording.md).

## QR-оплата: отдельный бейдж

Уточнение пользователя относится к CP-QR и MP-QR; конкретная конфигурация бейджа проверена по примеру MP-QR [2564:40064](https://www.figma.com/design/vdZ2J9y2d01k7UrmIbIfnR/SELECTOR?node-id=2564-40064).

- В ячейке использовать текст **«через QR Яндекс Пэй»**, не обычное «через Яндекс Пэй» для кнопки.
- Слева в Badge вместо YandexFilled поставить **Qr / Size=12 / Style=Outline**.
- Проверенный component key Qr: `443a2233e13e63426af6e57c106381b467200a37`; текущий узел компонента `2858:108370`. Использовать ключ для импорта, а не считать ID переносимым между файлами.
- Badge: Size=2xs, View=inverted-soft, Type=label, Font weight=Regular, Leading=true, Trailing=false.
- Бейдж находится во второй Line / Center Slot: 2nd line=true, Before=false, Center=true, After=false, Trailing=false; Line Size=4xs, Style=default.
- В этом примере третья строка выключена; общие правила переноса нескольких бейджей сохраняются.
- Подпись и QR-иконка описывают способ оплаты, не конкретный бренд или ставку 20%.
- Для CP-QR принадлежность к QR-сценарию задана пользователем; отдельно показанный здесь живой пример — MP-QR. Не переносить из MP-QR в CP-QR инструкцию деталки: различия «код в приложении магазина» и «код с таблички на кассе» сохраняются по references/qr-payment-wording.md.

## Бейдж «любая карта»

Проверено по [2683:71862](https://www.figma.com/design/vdZ2J9y2d01k7UrmIbIfnR/SELECTOR?node-id=2683-71862).

- Текст: **«любая карта»**, со строчной буквы, без «по».
- Слева: **MirFilled / Size=12 / Style=Outline**; component key `eeafd1875cc7eac1938aeed55ab991a7f9898fb4`.
- Это иконка MirFilled внутри Badge, не компонент Bank Card / Mir Default из Accent Bar деталки.
- Badge: Size=2xs, View=inverted-soft, Type=label, Font weight=Regular, Leading=true, Trailing=false.
- Во второй Line включён Center Slot с бейджем: Before=false, Center=true, After=false, Trailing=false; Size=4xs, Style=default.
- center / 2nd line=true; в примере 3d line=false. Общие правила переноса бейджей сохраняются.
- Использовать для самостоятельного метода «любая карта». **Не добавлять рядом с «через Яндекс Пэй» дублирующий бейдж «любая карта»**, поскольку этот сценарий уже подразумевает любую карту.
- Название партнёра и ставка примера не определяют оформление бейджа.

## Обязательная ширина ячеек и проверка после сборки

По уточнению пользователя 3 ноября 2026 **ширина самого List-item ячейки — строго 288 px**. Использовать FIXED по ширине; не растягивать до 328, 360 или ширины экрана/оформления.
